# نصب آسان پنل مستقل و نود OpenVPN

این نسخه آزمایشی برای **سرور جداگانه Ubuntu 24.04، amd64 و TUN فعال** است.
پیش از بهره‌برداری، تست تونل واقعی لازم است؛ محیط توسعه ابری TUN ندارد.
کد، کانتینر، ساختار دیتابیس و نود فعلی پاسارگارد تغییر داده نمی‌شوند. اتصال
نود جدید و ایجاد کاربران، از امکانات عادی پاسارگارد استفاده می‌کنند.

## دستور نصب

```sh
openvpnpa_installer=$(mktemp)
curl -fsSL https://raw.githubusercontent.com/zhilvanzhinos/openvpnpa/v0.2.0-beta.1/install.sh -o "$openvpnpa_installer" && sudo bash "$openvpnpa_installer" --public-ui
```

با `--public-ui` رابط مدیریت HTTPS از بیرون قابل دسترسی است. در حالت پیش‌فرض
این گزینه حذف می‌شود و رابط فقط روی `127.0.0.1` است. فرمان پیش‌بررسی فقط‌خواندنی:

```sh
bash "$openvpnpa_installer" --check
```

نصب‌کننده سیستم و TUN را ابتدا بررسی می‌کند؛ اگر TUN نباشد بدون تغییر متوقف
می‌شود. Docker موجود را restart یا جایگزین نمی‌کند؛ اگر Docker نصب نباشد از
بسته‌های رسمی Ubuntu یعنی `docker.io` و `docker-compose-v2` استفاده می‌کند.
اگر Docker موجود Compose v2 نداشته باشد، برای نصب افزونه متناسب متوقف می‌شود.
فایروال میزبان flush نمی‌شود و OpenVPN دیگری روی میزبان نصب نمی‌شود.

## اطلاعاتی که نصب‌کننده می‌پرسد

* IP عمومی IPv4 یا نام دامنه نود؛ همین مقدار در پروفایل و گواهی استفاده می‌شود.
* آدرس HTTPS پاسارگارد، بدون `/api` انتهایی. پیشوند مسیر نصب، اگر دارد، حفظ شود.
* توکن Bearer API پاسارگارد با اجازه ایجاد و خواندن کاربران مربوط. ورودی مخفی است.
* نام مدیر و رمز حداقل ۱۶ کاراکتری برای پنل محلی؛ ورودی رمز مخفی است.
* tag اختصاصی inbound، مثلاً `openvpnpa`؛ با tag نودهای فعلی مشترک نباشد.
* شناسه گروه اختصاصی، اگر قبلاً ساخته‌اید؛ می‌تواند تا مرحله اتصال خالی بماند.
* پورت‌های UDP پروفایل، TCP نود و HTTPS مدیریت؛ پیش‌فرض‌ها به ترتیب 1194، 62050، 8443.

توکن را از فرایند معمول احراز هویت/API پنل خود بگیرید. اگر منقضی شد، مقدار
`panel_token` را در `/opt/openvpnpa/config/config.json` با ویرایشگر امن عوض
کنید و فقط سرویس این پروژه را restart کنید. رمزها در آرگومان فرمان یا Git
قرار نمی‌گیرند. پیکربندی با مجوز 0600 و دایرکتوری آن با 0700 ساخته می‌شود.

## ورود به پنل محلی

در حالت public، `https://NODE_ADDRESS:8443` را باز کنید و با مشخصات انتخابی
وارد شوید. برای HTTPS یک CA اختصاصی ساخته می‌شود؛ فایل عمومی زیر را با
SSH/SCP دریافت و برای این اتصال به trust مرورگر اضافه کنید:

```text
/opt/openvpnpa/state/pki/ca.crt
```

کلید `ca.key`، کلید سرور و پروفایل‌های کاربران خصوصی‌اند. اعتبارسنجی گواهی
در پروفایل و ارتباط API خاموش نمی‌شود. برای رابط loopback می‌توانید از دستگاه
خود این تونل SSH را باز کنید و سپس `https://localhost:8443` را ببینید:

```sh
ssh -L 8443:127.0.0.1:8443 root@NODE_ADDRESS
```

## اتصال به پاسارگارد، فقط با منابع جدید

۱. در پنل محلی صفحه `/setup` را باز کنید. نمونه Core اختصاصی و اطلاعات نود
را می‌بینید. این صفحه فقط پس از احراز هویت قابل خواندن است.

۲. در پاسارگارد یک Core جدید با JSON بخش `config` نمونه بسازید. inbound آن
یک نشانگر `vless` با tag اختصاصی و listen برابر `127.0.0.1` است. این adapter
Xray اجرا نمی‌کند و پورت VLESS باز نمی‌کند؛ نشانگر برای انتخاب و همگام‌سازی
کاربران از مسیر استاندارد پنل است. Core موجود را ویرایش نکنید.

۳. یک نود **جدید** با connection_type برابر `rest` ثبت کنید. address، port،
API key و server_ca را از `/setup` بردارید؛ core_config_id باید شناسه Core
جدید باشد. ضریب مصرف ۱ و keep_alive برابر ۶۰ باشد. api_port را همان port
قرار دهید. بروزرسانی core/node از پاسارگارد پشتیبانی نمی‌شود و نباید روی این
adapter اجرا شود. مقادیر uptime/تعداد CPU واقعی‌اند؛ فیلدهای اختصاصی حافظه Go
و سرعت سیستم که اندازه‌گیری نمی‌شوند صفر گزارش می‌شوند.

۴. یک گروه جدید بسازید که فقط inbound نشانگر این نود را داشته باشد. شناسه
گروه را در فرم `/setup` پنل محلی ذخیره کنید؛ restart لازم نیست. برای کاربر
فقط OpenVPN همین گروه کافی است. برای کاربر مشترک، گروه جدید را در کنار
گروه‌های قبلی او قرار دهید؛ گروه‌های فعلی را حذف نکنید.

۵. در پنل محلی کاربر بسازید یا با نام کاربری موجود او را اضافه کنید و فایل
`.ovpn` را بگیرید. وضعیت دسترسی تا دریافت Start و همگام‌سازی صحیح نود بسته
می‌ماند. اتصال کاربر موجود، گروه‌های او را خودکار تغییر نمی‌دهد.

در فایروال سرور جدا، UDP پورت VPN لازم است. TCP پورت نود باید از سمت
پاسارگارد قابل دسترسی باشد؛ آن را به مبدأهای لازم محدود کنید. رابط مدیریت
تنها در صورت انتخاب public به دسترسی بیرونی نیاز دارد. هیچ قاعده فایروال
میزبان در نصب‌کننده بازنویسی نمی‌شود. NAT فقط داخل namespace کانتینر است.

## مدل مصرف و دسترسی

هر گواهی کلاینت CN عددی برابر UID پاسارگارد دارد. OpenVPN ابتدا گواهی را
اعتبارسنجی می‌کند؛ سپس adapter با مجوز inbound دریافت‌شده از نود و وضعیت
تازه API اتصال را تأیید می‌کند. تنها وضعیت `active` پشتیبانی می‌شود؛
`on_hold` در این نسخه باز نمی‌شود و فعال‌سازی مبتنی بر اولین مصرف پیاده نشده است.

نمونه مصرف هر ثانیه و نمونه نهایی DISCONNECT در SQLite پایدار ثبت می‌شوند.
دلتاها با `Stat.name=UID` از REST نود خوانده می‌شوند و در سهمیه اصلی جمع
می‌شوند. این شمارنده بایت مدیریت OpenVPN است و ممکن است سربار پروتکل داشته
باشد. API مدیریت فقط کاربر می‌سازد/می‌خواند و هیچ مجموع مصرفی را بازنویسی نمی‌کند.

حذف inbound فوراً فرمان قطع session فعال را می‌فرستد. وضعیت API هر ۱۵ ثانیه
تازه می‌شود؛ cache که بیش از ۴۵ ثانیه قدیمی باشد دسترسی نمی‌دهد. نبود تماس
نود برای ۱۲۰ ثانیه (lease محلی) Start تازه را لازم می‌کند. قطع کانال مدیریت
یا مرگ OpenVPN، کل سرویس را متوقف می‌کند تا Docker آن را از نو راه بیندازد.
پس از ری‌استارت، مجوز تا Start تازه از پنل بسته می‌ماند.

گزارش `reset=True` پروتکل اصلی ACK پس از commit ندارد. حفظ مصرف ثبت‌شده
در SQLite، تضمین تحویل دقیق آن به دیتابیس پنل نیست. replay خودکار انجام
نمی‌شود و گزارش‌های تحویل‌داده‌شده برای audit می‌مانند. این محدودیت و ترافیک
بین آخرین نمونه تا crash در [گزارش سازگاری](compatibility.fa.md) توضیح داده شده‌اند.

## مدیریت، داده‌ها و نصب مجدد

```sh
sudo /opt/openvpnpa/manage ps
sudo /opt/openvpnpa/manage logs --tail=100 node
sudo /opt/openvpnpa/manage restart node
sudo /opt/openvpnpa/manage stop node
```

پیکربندی در `/opt/openvpnpa/config`، SQLite و PKI در `/opt/openvpnpa/state`
و کد نسخه ثابت در `/opt/openvpnpa/releases/v0.2.0-beta.1` است. حذف کانتینر
این داده‌ها را حذف نمی‌کند. برای backup سازگار، سرویس این پروژه را متوقف
کنید و config و state را با هم، با حفاظت از کلیدهای خصوصی، آرشیو کنید.
فایل audit و tombstoneهای مصرف در این beta خودکار پاک نمی‌شوند؛ فضای دیسک
باید برای حجم کاربران و تعداد sessionها کافی باشد. لاگ کانتینر محدود شده است.

اجرای دوباره نصب‌کننده تنظیمات و PKI موجود را حفظ می‌کند و روی همان نسخه
می‌ماند. به‌روزرسانی بین نسخه‌ها/مهاجرت خودکار در این beta ارائه نشده است.
گواهی سرور و کلاینت یک‌ساله‌اند؛ صدور مجدد پیش از انقضا یک عملیات نگهداری
جداست و این نسخه آن را خودکار انجام نمی‌دهد. همه پروفایل‌های یک UID هنگام
حذف دسترسی همان UID بسته می‌شوند؛ ابطال مستقل یک دستگاه هنوز ارائه نشده است.

## آزمون پذیرش روی VPS آزمایشی

ساخت تصویر، تست‌های پروتکل و UI جای این موارد را نمی‌گیرند:

* اتصال کلاینت واقعی با پروفایل و انتقال یک فایل با حجم معلوم از تونل.
* قطع عادی و خواندن دلتا نهایی؛ قطع و وصل گزارش نود و بررسی audit.
* ری‌استارت سرویس و بررسی حفظ دلتاهای محلی و رد اتصال تا Start تازه.
* مصرف هم‌زمان V2Ray و OpenVPN با یک UID و کنترل شمارنده پنل.
* انقضا و اتمام حجم و تأیید قطع session واقعی و رد اتصال مجدد.

نسخه فعال پاسارگارد هنوز مشخص نشده و تست روی پنل فعال انجام نشده است.
استقرار روی سرور فعال همچنان مرحله جدا باقی می‌ماند.
