# OpenVPNPA: OpenVPN node + independent management UI

**وضعیت: نسخه آزمایشی `v0.2.0-beta.9`؛ پنل مدیریت و adapter نود پیاده‌سازی
شده‌اند. تونل واقعی روی این محیط ابری، به علت نبود TUN، تأیید نشده است.**

نصب روی یک Ubuntu 24.04 مستقل با معماری amd64 و TUN فعال:

```sh
curl -fsSL https://raw.githubusercontent.com/zhilvanzhinos/openvpnpa/v0.2.0-beta.9/install.sh | sudo bash
```

این یک دستور تمام مراحل نصب محلی را اجرا می‌کند و سؤال‌ها را به فینگلیش
داخل ترمینال می‌پرسد. ورود به پاسارگارد با نام کاربری/رمز یا توکن API ممکن
است؛ در حالت اول توکن خودکار دریافت می‌شود و رمز اصلی ذخیره نمی‌شود.
در پایان، آدرس پنل، پورت‌ها، **API Key** و متن کامل **Certificate** چاپ
می‌شوند. پس از نصب، پنل روی `https://NODE_ADDRESS:8443` است. گواهی CA محلی
را از مسیر اعلام‌شده از طریق SSH دریافت و برای همین اتصال اعتماد کنید؛
کلید خصوصی CA را جابه‌جا نکنید. نصب‌کننده درباره دسترسی بیرونی پنل سؤال
می‌کند؛ پاسخ n آن را فقط روی loopback نگه می‌دارد.

آپدیت نصب موجود به آخرین تغییرات GitHub، بدون ورود دوباره تنظیمات:

```sh
curl -fsSL https://raw.githubusercontent.com/zhilvanzhinos/openvpnpa/main/update.sh | sudo bash
```

پس از اولین آپدیت موفق، `sudo /opt/openvpnpa/update` هم همین کار را انجام
می‌دهد. داده‌ها و گواهی‌ها حفظ می‌شوند؛ جایگزینی سرویس یک قطع کوتاه دارد.
[جزئیات backup و rollback](docs/update.fa.md).

در صفحه `/setup`، مشخصات **Core، گروه و نود جدید** برای ثبت در پاسارگارد
نمایش داده می‌شود. شناسه گروه را همان‌جا ذخیره کنید؛ سپس کاربر بسازید یا
کاربر موجود را وصل کنید و `.ovpn` بگیرید. نصب‌کننده پنل فعال را خودکار
تغییر نمی‌دهد. [راهنمای نصب و اتصال](docs/install.fa.md) را ببینید.

طبق کد رسمی بررسی‌شده، جمع‌شدن مصرف OpenVPN و V2Ray با شناسه عددی مشترک
امکان‌پذیر است. تضمین هم‌زمان «عدم اتلاف مصرف» و «عدم دوباره‌شماری» در
قطع گزارش با پروتکل فعلی نود، بدون تغییر پنل، ممکن نیست. نتیجه کامل و مرز
آزمایش‌ها در [گزارش سازگاری](docs/compatibility.fa.md) آمده است.

پنل جدا فقط از API رسمی کاربر می‌سازد و وضعیت را می‌خواند؛ مصرف از REST نود
گزارش می‌شود. گواهی هر کاربر به UID پاسارگارد متصل است. API مدیریت، مصرف را
بازنویسی نمی‌کند. مجوز inbound و وضعیت تازه API هر دو برای اتصال لازم‌اند.

کانتینر آزمایش زیر مستقل از کانتینر سرویس در `deploy/` است؛ هیچ پورتی منتشر
نمی‌کند، به پنل واقعی وصل نمی‌شود و بدون دسترسی TUN اجرا می‌شود:

```sh
docker compose build
docker compose run --rm compatibility
```

در محیط ابری دارای پراکسی HTTPS، گواهی قابل اعتماد میزبان فقط هنگام build
mount می‌شود و در تصویر ذخیره نمی‌شود؛ TLS verification فعال می‌ماند:

```sh
docker compose -f compose.yaml -f compose.cloud.yaml build
docker compose run --rm compatibility
```

توسعه محلی (Python 3.12+):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -v
```

آزمایش OpenVPN management در صورت نبودن باینری در میزبان skip می‌شود؛ در
تصویر Docker وابستگی‌ها نصب هستند. تست‌های HTTPS از API شبیه‌سازی‌شده
پاسارگارد و رویدادهای مدیریت نمونه استفاده می‌کنند. بررسی تنظیمات سرور
واقعی تا مرز TUN اجرا می‌شود؛ انتقال ترافیک یا قطع تونل واقعی تأیید نشده است.

اجرای تست‌ها هیچ اعتبارنامه پنل فعال لازم ندارد. فایل‌های نمونه پروتکل رسمی
در [vendor](vendor/README.md) با commit و hash منبع ثبت شده‌اند.

نسخه اعلام‌شده پنل کاربر `v5.5.1` است؛ دسترسی به پنل زنده در این محیط وجود ندارد. سازگاری REST با SDK رسمی جداگانه آزمایش
می‌شود؛ این نتیجه جای تست پنل فعال و آزمایش تونل واقعی روی ماشین جدا را
نمی‌گیرد. محدودیت تحویل گزارش فعلی در نسخه آزمایشی حفظ و مستند شده است.

در نسخه beta.9، همه کاربران قابل‌مشاهده با توکن API، از تمام صفحات
`/api/users` وارد فهرست مستقل می‌شوند؛ این کار در شروع سرویس و پس از هر
چرخه همگام‌سازی با فاصله ۱۵ ثانیه تکرار می‌شود و دکمه تازه‌سازی نیز آن را
اجرا می‌کند. UID اصلی حفظ می‌شود؛ حساب جدید یا عضویت گروه خودکار ساخته
نمی‌شود. توکن باید مجوز خواندن همه کاربران موردنظر را داشته باشد.
ورود به فهرست به‌تنهایی مجوز OpenVPN نیست: Start تازه، sync شامل inbound
اختصاصی، وضعیت فعال و سهمیه معتبر همچنان لازم‌اند.

در صفحه اصلی، «آدرس اتصال کلاینت OpenVPN» برای IP/دامنه تانل و پورت UDP
است. مقدار خالی از `public_host` و پورت اصلی استفاده می‌کند. این تنظیم فقط
خط `remote` فایل‌های دانلودشده بعدی را تغییر می‌دهد و فایل قبلی را بازنویسی
نمی‌کند؛ پورت شنود سرور، گواهی و آدرس ارتباط با پاسارگارد مستقل می‌مانند.
